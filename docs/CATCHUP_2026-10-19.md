## Findings

1. **Source-monitor freshness loop is broken after old PRs close.** Both daily
   workflows succeed and push new snapshots to their automation branches, but
   their `gh pr view "$BRANCH"` condition accepts merged/closed PRs. The source
   workflow run on 2026-10-19 pushed commit `ba4e88b` and then printed PR #22,
   which was merged on 2026-07-01. The Toccata branch resolves to closed,
   unmerged PR #12. There are currently no open PRs. Meanwhile main's source
   snapshot is dated 2026-07-01 and its Toccata snapshot 2026-06-30. Evidence:
   `.github/workflows/kaspa-source-intelligence.yml`,
   `.github/workflows/toccata-source-monitor.yml`, and
   https://github.com/gryszzz/Kaspa-Ai-Agent-Skill/actions/runs/39305879563.
2. **KaspaScript remains a preview implementation.** `sdk/Cargo.toml` still uses
   optional Kaspa `0.15.0` dependencies. `docs/PROJECT_STATUS.md` still lists
   `v2.0.1` as current and does not claim mainnet activation. Its transaction
   facade and production covenant/ZK/sequencing lowering remain explicitly
   incomplete. Protocol activation alone cannot unlock those integration gates.
3. **Installed skill, repository, and published release have drifted.** The local
   source inventory still ends with a pre-activation June 30 pulse; repository
   references include the later activation evidence. Identical manifest versions
   do not establish identical skill contents. Sync requires reviewing differences
   and preserving local changes.
4. **Monitoring scope misses important new work.** The source monitor tracks
   seven repositories, labels Silverscript experimental, and checks only Rusty
   Kaspa releases. It does not track Silverscript releases, Argent, KCCs, or the
   privacy initiative. Official/core sources and community experiments must keep
   distinct evidence classifications when added.

## Recommended Build Order

1. Correct both workflows to find an explicitly open PR for the branch and create
   a fresh PR when the only previous PR is merged or closed. Add regression
   coverage for all three states; review current automation snapshots.
2. Refresh the skill's dated references and watchlist, verify packaging, then
   reconcile the installed copy with a backup and a conflict-aware sync.
3. Add an isolated Rusty Kaspa `v2.1.0` compatibility probe and Silverscript
   `v1.0.0` interoperability tests. Preserve explicit UTXO plans, signing previews,
   deterministic artifacts, and indexer requirements as KaspaScript strengths.
4. Validate one real TN10 covenant lifecycle, including rejected transitions,
   replay, wrong-network handling, fees, and indexer reconciliation, before
   broadening production claims.
5. Track privacy as a separate experimental integration. Reproduce public proof
   and recovery evidence before depending on it for user funds.

Requirement anchor: `docs/kaspa/mainnet-readiness-gate.md` requires verified
transaction parsing, covenant-aware construction, mass/fee compatibility,
reorg-safe indexing, and signing UX independently of protocol activation.
